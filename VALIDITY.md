# Does every run work? The evidence

Shao, 13 Oct: "97% kept" is not evidence on its own. This page is what
"kept" means, how we know the checks work, and what a person sees when
looking at the runs. Numbers from `GATE.md`, `FACTS.md`,
`figures/cards/*.json`; all regenerated by the scripts named.

## 1. What a kept run has passed

Every launch goes through the same code (`harness/loop.py`); a run is kept
only if all of these pass:

| Check | What it verifies | Code |
|---|---|---|
| Machine | GPU memory, disk, no leftover containers or networks, before launch | `environment.py` |
| Finished | exit code 0, a metrics file written | `read_state.py`, `postflight.py` |
| Settings landed | the simulator's resolved config equals the request (delay, controller, control step, seed) | `read_state.py` |
| Retiming happened | the runtime logged the requested actor as retimed, at the requested shift and speed | `read_state.py` |
| Ego speed | the measured speed at the hand-off matches the requested multiple (0.05 m/s + 2%) | `physics.py` |
| Physics | acceleration, yaw rate, reported against measured speed, the policy really drove, the controller tracked the plan it was given | `physics.py` |
| Learned rules | every rule the auditor proposed and a person admitted | `rules.py`, `rules/promoted.json` |
| Batch audit | the auditor reviews a finished batch for runs that are wrong the same way | `audit.py` |

## 2. The checks catch bad runs (planted faults)

Campaigns C1-C3 (29 Sep-6 Oct, FACTS "Campaign C3"): 225 runs broken on
purpose in five silent ways (wrong delay, missing metrics, wrong controller,
...), each run looking normal.

| | invalid runs kept |
|---|---|
| no gate (keep exit code 0) | 225 |
| per-run gate | 40 |
| gate + batch audit | **0** (one-sided 95% bound on a survivor: 1.3%) |

Figure: `figures/campaign_invalid.png`. Physics check: 0 false alarms on
256 clean runs, 6 of 6 silent motion faults caught (FACTS "Physics checks").

## 4. What is in the kept runs

The gate proves a run did what was asked and moved like a car. It does not
prove a contact is the policy's fault. Every kept run of the six method
studies, all methods pooled, each run in the first category that fits, in
the column order (`figures/paper/fig_outcome_mix.pdf`,
`figures/cards/outcome_mix.json`, `harness/paper_figures.py`):

| study | kept | AI failure | of which ego > 3.5 m off the recording | contact begun before the AI drove | contact with a car that stopped dead | rear-ended by a replayed car | no contact |
|---|---|---|---|---|---|---|---|
| pedestrian | 654 | 68% | 33% | 0% | 0% | 0% | 32% |
| cut-in | 1025 | 21% | 3% | 13% | 5% | 28% | 33% |
| car ahead braking | 1001 | 15% | 2% | 17% | 0% | 29% | 38% |
| pedestrian, 2 Hz | 625 | 41% | 9% | 0% | 0% | 4% | 55% |
| cut-in, 2 Hz | 701 | 14% | 0% | 13% | 2% | 38% | 32% |
| car ahead braking, 2 Hz | 637 | 15% | 0% | 11% | 0% | 36% | 38% |

What this says:
- **Replayed traffic does not react.** In the car studies a replayed car
  drives into a slowed ego in 27-38% of kept runs. The scorer does not count
  these (problem 25), but a third of runs are spent where the other cars
  cannot respond. Reactive traffic (AlpaSim's CATK model) is the fix to
  weigh; it costs the near-determinism of replay.
- **Retiming can start a contact before the AI drives** (11-17% in the car
  studies): a lead car slowed or moved later meets the ego still replaying
  the human's path. Not counted (problem 30); a pre-launch overlap check
  would stop spending runs on them.
- **Pedestrian failures often happen far from the recording.** In 213 of 442
  counted pedestrian failures at 10 Hz the ego was more than 3.5 m off the
  recorded path, where the neural rendering is less certain. Flagged on
  every such run (`possible_artifact`), not removed.

- **Retimed cars can freeze in their lane (problem 31).** The retiming
  holds a sped-up car's last pose once its recording runs out, so it stops
  dead in one step. Found from the case cards (13 Oct). Since 14 Oct the
  scorer does not count a contact with a road user that stopped dead from
  faster than walking pace (`outer.outcome`, `physics.stopped_dead`): 89
  cut-in runs at 10 Hz, 44 at 2 Hz, none in lead vehicle
  (`held_actors.json`). The AI methods had favoured these settings; under
  the rule cut-in hybrid confirms 3, 3, 3 rather than 4, 5, 4.

## 5. What a person sees

- **Hardest cases**: one card per confirmed hardest setting
  (`figures/cards/hardest/README.md`, 19 cards).
- **Spot check**: 20 kept runs drawn at random
  (`figures/cards/spot/README.md`). Of the 20: 5 counted failures (2 at-fault
  contacts, 3 off-road), 10 contacts not counted (rear-ended or begun before
  the hand-off), 5 with no contact. Each card shows paths from above,
  speeds, gap, acceleration, offset from the human, and the camera.
- **Blind human labels**: Griffin's 60 (10 done), to compare with the
  scorer and the triage.
