# Results

Four ways a finished-looking run can lie. Every count below is from a file already on disk. No new rollout.

| Lie | What a reader would have concluded | What the gate does |
|---|---|---|
| Context length 1 | The nominal driver crashes. `src/wizard/configs/driver/vavam.yaml` sets `inference.context_length: 1`. `diag/nominal_run_1` through `diag/nominal_run_10` each have that value in `driver-config.yaml`. `collision_at_fault` is 1.00 in `diag/nominal_run_{2,3,4,5,6,7,9,10}/aggregate/metrics_results.txt` and 0.00 in runs 1 and 8: 8 of 10. | `research/harness/preflight.py` rejects `context_length` other than 8. `research/harness/l7_trace.jsonl` line 1 is CONFIGURE, `preflight_rejected: context_length must be 8, got 1`. `research/harness/l8_trace.jsonl` records that case with `launched` false. |
| Latency regex | 162 of 212 scored runs had zero injected delay, so the crashes are not a latency effect. `cp2_results.parquet` has 212 rows and `planner_delay_us` 0 on 162 of them (50 are nonzero). `researchideas.md` §0 says the column was the first `re.search(r"planner_delay_us:\s*(\d+)", content)` hit. `src/wizard/configs/base_config.yaml` line 333 is `planner_delay_us: 0`. The plot those rows fed is `cp2_failure_boundary.png`. On the 212 saved `wizard-config.yaml` files, `runtime.simulation_config.planner_delay_us` matches the parquet column. | `research/harness/preflight.py` rejects a launch when `hydra_delay` does not equal `request_delay`. `research/harness/analyze_cp2.py` reads `runtime.simulation_config.planner_delay_us`. `research/harness/test_analyze_cp2.py` builds a file with top-level `planner_delay_us: 0` and resolved `150000`; `extract_resolved_config` returns 150000. |
| Missing metrics | The study is the runs that wrote a table. `autolab_experiments/` has 273 run directories. 60 of them contain no `metrics.parquet`, including `autolab_experiments/run_001_145815`. 60/273 is 22%. The other 213 wrote a parquet. | `research/harness/postflight.py` fails the run when no metrics parquet is present. `research/harness/l7_trace.jsonl` line 2 is RE-RUN on `research/harness/fixtures/no_metrics`. `diag/l8_ctx8` has no metrics parquet; `research/harness/l8_trace.jsonl` records RE-RUN for it. |
| Solver status `solved` | Every control step succeeded. `HANDOFF.md` §3.1 quotes the old rule: `status = "solved"` whenever `make_step()` did not raise. `src/controller/alpasim_controller/mpc_impl/nonlinear_mpc.py` sets `ipopt.max_iter` to 30, and a cap or an infeasible return does not raise. | The same file now maps `solver_stats` to `solved`, `max_iter:<n>`, `infeasible`, or `unconverged:...`. `diag/solver_status_verify/controller/alpasim_controller_d8ee28e6-b2c9-11f1-b35d-5316127291ca.csv` has 195 data rows, header ending `solve_time_ms,status`, and `status` is `solved` on all 195. `validate_postflight("diag/solver_status_verify")` returns `solver_status` None: `research/harness/postflight.py` looks for the CSV at `run_dir.parent.parent/controller`, and this file is at `diag/solver_status_verify/controller/`. |
