\begin{abstract}
\pending{write last, about 150 words.} Four sentences:
\begin{itemize}
\item \textbf{Problem.} Stress testing an end-to-end driving policy in closed loop takes thousands of short simulation runs; done by hand it is slow, and done unattended it fails silently.
\item \textbf{What we built.} SimGate, an AI agent that runs the whole campaign: plans a study from a plain-English brief, picks the next tests, heals failed runs, checks every result, and explains each failure. The agent only chooses from fixed menus; code checks each choice and scripts act on it.
\item \textbf{Evidence.} On AlpaSim with the VaVAM policy: 9,790 runs over 15 days, 99.1\% ending with a valid result; 290 of 309 operational failures healed with no person; no planted invalid run kept.
\item \textbf{Finding.} Where failures are rare, letting the agent choose the next tests confirms the hardest cases far sooner than rules, random search or Optuna (three-knob study: 24 of 25 against 7 for random and 0 for rules).
\end{itemize}
\end{abstract}

\section{Introduction}\label{sec:intro}
\pending{about 0.75 page}
\begin{itemize}
\item \textbf{Why stress testing.} Accelerated testing finds rare failures without driving millions of miles \pending{cite NADE, D2RL, AST}. Neural-reconstruction simulators now let a camera-to-trajectory policy drive real recorded scenes in closed loop~\cite{alpasim} \pending{cite NeuroNCAP, HUGSIM}.
\item \textbf{The gap.} A campaign is thousands of runs. Someone must choose them, relaunch the ones that crash, and make sure each counted run really tested what it claims. Unattended, this fails silently: in our own early data a misconfigured model, a delay that never applied and missing results all looked like findings.
\item \textbf{Our approach.} Hand the whole campaign to an AI agent, and make it trustworthy by design: every job the agent does is a contract with a fixed menu of answers, checked by code before anything happens.
\item \textbf{Contributions} (match \texttt{OUTLINE.md}):
  \begin{enumerate}
  \item An agent that runs AV stress testing end to end, unattended, on a closed-loop end-to-end policy in a neural-reconstruction simulator.
  \item An action design for the agent: skills as markdown contracts with finite menus, code checks and script execution; checked exhaustively.
  \item Evidence that the agent discovers and confirms corner cases faster where failures are rare, at an equal budget against rules, random search and Optuna.
  \item Results a person can check: a ledger of every failure the agent handled and a case card for every confirmed hardest case.
  \end{enumerate}
\item \textbf{Wording to avoid} (\texttt{OUTLINE.md}): no ``first'' for full-pipeline LLM testing, agentic scenario generation, LLM vs rules comparison, or closed-loop neural-reconstruction testing.
\end{itemize}

\subsection{Setting}
\begin{itemize}
\item AlpaSim~\cite{alpasim} replays real recorded scenes in neural reconstruction; VaVAM~\cite{bartoccioni2025vavam} drives from camera to trajectory; a linear MPC tracks the plan; recorded traffic is replayed (does not react).
\item \textbf{Knobs}, each read back from the run's own logs: a recorded actor's timing and speed, the ego's speed at hand-off, lateral plan shift. 2\,Hz (VaVAM's own rate) and 10\,Hz.
\item \textbf{Studies} as OpenSCENARIO 1.4 parameter distributions, mapped to Euro NCAP tests: pedestrian (AEB VRU), cut-in, car ahead braking (AEB C2C rear), lane keeping (LSS), and a three-knob car-conflict study with rare failures. Intersection crossing (AEB C2C crossing): seven methods, one repeat each; every method confirms about 2 of 5, so it adds coverage, not a method comparison.
\end{itemize}

\subsection{Action design: skills as checked contracts}\label{sec:skills}
\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{figures/fig_skill_contract.png}
\caption{\pending{redraw at column width} One skill contract (diagnose a failed run). The same five parts structure all seven contracts.}
\label{fig:contract}
\end{figure}
\begin{itemize}
\item Every job the agent does has the same five parts: \emph{when} code calls it; \emph{what it sees}; \emph{what it may answer} (a fixed menu or schema); \emph{who checks} the answer (plain code); \emph{who acts} (a script, never the agent).
\item Seven contracts: diagnose a failed run, plan a study, choose the next runs, audit a batch, triage a failure, tag a scene, write the report. Table or short list \pending{decide}.
\item \textbf{Inner loop, the diagnose contract.} Sees the failure status, config, error lines and a machine snapshot, with read-only tools. Answers one of five skills: RE-RUN, CONFIGURE (allowed keys only), CLEANUP\_ENV, RESTART\_CLEANUP, HALT. \texttt{validate\_diagnosis.py} rejects, e.g., changing what the run measures or a second cleanup.
\item \textbf{Why finite menus matter.} Every answer the agent could give, at every failure state, was tried: 3,822 transitions, 0 violations, at most 3 launches per run.
\item \textbf{The gate.} A run counts only if the requested scenario provably happened (read back from logs) and the motion is physically plausible; a batch audit catches what the per-run gate misses.
\item Packaged as Claude Agent Skills; given only the skills and a real input, Claude picked the right one 22 of 22 times \pending{keep or cut for space}.
\end{itemize}

\subsection{Outer loop: choosing the next runs}
\begin{itemize}
\item Each study: find the 5 hardest cases within a fixed budget (50--60 runs, rounds of 10). A \emph{hardest case} is a setting, on its own scene, that the policy fails when rerun: confirmed once the 90\% Wilson interval of its failure rate lies above one half (3 failures in 3 runs is the fewest). Two scores: hardest cases confirmed within the budget (where failures are rare), and runs to confirm all 5 (where most methods finish). Each method repeated from scratch 5 times.
\item \textbf{Methods}, equal budget, same gate: rules; random + repeat; Optuna + repeat; the AI choosing freely (\textbf{AI (ours)}; its instructions were revised once, on the three 10\,Hz studies, to add each failure's triage and the scenes' facts, and frozen before the two test studies ran; the first version is reported as ``AI, first prompt''); hybrid (the AI choosing among the rules' candidates); Optuna + AI.
\item \textbf{What counts as a failure:} policy at fault after it takes over; contacts begun before the hand-off, rear-ends by replayed traffic, and contacts with a car the retiming held still are not counted (Sec.~\ref{sec:lessons}).
\end{itemize}

\section{Limitations}\label{sec:limits}
\begin{itemize}
\item One policy (VaVAM; a larger model does not fit 24\,GB).
\item Replayed traffic does not react; retiming moves only recorded actors; road geometry is chosen, not varied.
\item Unprotected left turns: 2 of 250 scenes \pending{and intersection crossing, if not run}.
\item Pedestrian failures are often far from the recording, where rendering is less certain (flagged).
\item Three to five repeats per arm: small samples. With five, an exact two-sided test cannot go below p = 0.008; we report the planned comparisons with Holm correction.
\item Human check of the scorer and triage: \pending{Griffin's spot-check verdicts and blind labels}.
\end{itemize}

\section{Conclusion}\label{sec:conclusion}
\begin{itemize}
\item An agent can run stress testing of a driving policy end to end, unattended, if each action is a checked choice from a fixed menu.
\item Letting it choose the next tests pays off most where failures are rare.
\item Code, contracts, every run and every failure ledger are public \pending{repo link, and whether to release before review}.
\end{itemize}
